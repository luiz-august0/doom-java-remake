# 09 — Testing and quality

Tools: **JUnit 5 + AssertJ** (all modules), JMH only in `doom-bench` (ADR-015). No other test library.

## 1. Pyramid

| Level | What it covers | Where | Needs an IWAD? |
|-------|----------------|-------|----------------|
| Unit | `math` (tables, `mul`/`div` with overflow, `PointToAngle`, `Angle.*`), parsing of each lump format, RNG, MUS → events, mixer, OPL3 (vectors) | each module, `*Test` | No |
| Definition equivalence | Definitions DSL × `info.c` ([ADR-014](01-decisions.md#adr-014--game-definitions-in-a-custom-format-verified-against-the-original)) | `doom-game`, `DefsEquivalenceTest` | No (committed snapshot) |
| Component | Physics, collision, doors, lifts and AI on **synthetic maps** built in code (`MapBuilder` in `doom-game`'s test sources, ADR-022) | `doom-game`, `*Test` | No |
| Demo sync | Per-tic trace against the oracle (§2) | `doom-game`, `*IT` | Freedoom in CI; commercial ones locally |
| Golden frames | Renderer in vanilla mode × oracle framebuffer (§3) | `doom-render`, `*IT` | Same |
| Smoke | Headless title loop for 10,000 tics on each available IWAD, without exceptions; `-warp` to every map, 350 tics standing still | `doom-engine`, `*IT` | Same |
| Save/load | Round trip + deterministic continuation ([08 §2.3](08-persistence.md#23-compatibility-and-validation)) | `doom-game`, `*IT` | Same |
| Performance | `-timedemo` + JMH of the *drawers* | `doom-bench`, manual | Yes |
| Allocation | JFR on headless `-timedemo`: zero allocation samples in renderer, mixer and loop | `doom-engine`, `*IT` | Yes |

**(ADR-022)** Every `*IT` lives in the `doom-it` module; the "Where" column names the module under test.

**Synthetic maps** are what make the simulation testable without an IWAD: `MapBuilder.room(…)`, `.door(…)`, `.lift(…)`, `.spawn(MonsterType, x, y)` generate the same structures that the `LevelLoader` would produce, including a simple BSP, blockmap and reject.
A test writes `TicCmd`s and checks the result with AssertJ (`assertThat(player.z()).isEqualTo(…)`).

## 2. Demo sync (the test that matters)

### 2.1 Oracle

- **Chocolate Doom** at a pinned version, compiled locally from the source code, with the `tools/oracle/chocolate-trace.patch` patch (small, kept in the repo).
- The patch adds `-trace <file>`: at the end of each game tic it writes one line of the record below. It also adds `-dumpframe <tic> <file>`, which saves the indexed 320×200 framebuffer at a given tic (§3).
- `tools/oracle/build.sh` clones, applies the patch and compiles (macOS and Linux). No third-party binary is committed.

### 2.2 Per-tic record

```
gametic;rng;leveltime;
p0.x;p0.y;p0.z;p0.angle;p0.momx;p0.momy;p0.health;p0.armor;p0.weapon;p0.ammo[4];…(p1..p3 if present)
actors.count;actors.hash
```

- `actors.hash`: FNV-1a hash of `(type, x, y, z, angle, state, health, flags)` of all actors **in thinker-list order**. With this, any difference in order also shows up.
- Text file `.trace.gz` per demo. Reference traces generated by the oracle are kept in `testdata/traces/` (they are only numbers; no game content).

### 2.3 Comparison

`doom-tools trace-diff ref.trace.gz ours.trace.gz` reports the **first divergent tic and the first divergent field** and shows the neighbouring lines.
To debug the actors hash, `-trace-verbose` dumps all the actors of the divergent tic on both sides.

### 2.4 Corpus

| Set | Where it runs |
|-----|---------------|
| Demos of the Freedoom IWADs (Phase 1 and 2) + demos recorded by the oracle on the Freedoom maps (covering weapons, doors, lifts, teleporters, all monsters) | **CI** (Freedoom is BSD and can be downloaded in CI) |
| `DEMO1`–`DEMO4` of DOOM.WAD/Ultimate, DOOM2.WAD, TNT.WAD, PLUTONIA.WAD, DOOM1.WAD | Local (`DOOM_IWAD_DIR`) |
| Community vanilla-compatibility demos (curated, downloaded by `doom-tools fetch-demos` into a local cache, not committed) | Local, before each release |

**Gate:** no demo of the available corpus may diverge. A demo that also diverges in the oracle (for example, due to a version difference) goes on the exceptions list with a justification.

## 3. Golden frames

- Oracle: `-dumpframe` at chosen tics of demos (map start, combat, dark sector, invisibility, sky, automap, intermission, menu).
- Remake: `doom-tools frame-dump` in vanilla mode (320×200, 4:3, `precisionFixes = false`, no interpolation).
- Criterion: **byte-for-byte equality** of the indexed framebuffer. On failure, it generates a side-by-side PNG + a difference mask.
- Cases known to be impossible to match (out-of-texture memory reads in the original, Medusa effect) are left out of the set, with a justification.

## 4. Performance and allocation

- `-timedemo` prints tics, time and FPS. `doom-tools bench-suite` runs a fixed list of demos at 3 resolutions and writes a CSV to `bench-results/` for comparison between commits (locally; CI runners are too noisy to be a *gate*).
- JMH (`doom-bench`): `ColumnDrawer`, `SpanDrawer`, framebuffer layouts (row × transposed), *views* × direct access (to validate ADR-004).
- Allocation: `*IT` test with JFR (`jdk.ObjectAllocationSample`) during 2,000 tics of headless `-timedemo`. It fails if there are samples in renderer, mixer or loop packages.

## 5. CI (GitHub Actions)

| Job | When |
|-----|------|
| `mvn verify` (unit, equivalence, component) on Linux, macOS, Windows | every push |
| Freedoom suite (demos + golden frames + smoke) | every push to `main` and on PRs |
| `jpackage` per OS | `v*` tags |

## 6. Definition of done (per PR)

- `mvn verify` green on the 3 OSes.
- No new demo diverging; if the PR touches the simulation, also run the local corpus of commercial IWADs and report the result in the PR.
- New simulation code with `@VanillaRef`; preserved bugs with `// VANILLA-BUG:`; deviations with `// DIVERGE:` + an entry in `docs/divergences.md`.
- No new dependency outside the ADR-021 list (the *enforcer* blocks it).
