# W4-R divergences

| area | original behaviour | ours | reason | reference |
|---|---|---|---|---|
| Wall scale and columns (`precisionFixes`, not in vanilla mode) | `R_ScaleFromGlobalAngle`: 32-bit fixed point at the wall ends, linear 16.16 step, texture column from `finetangent` of an 8192-step angle | exact line geometry in `double`: scale `(r.n)/dist` and texture position `(eye-v1).T + dist*(r.T)/(r.n)` per column from the level's line (not the rounded seg vertices); wall columns step the texture with 32 fractional bits | removes wall wiggle and swimming textures at high resolution | spec 04 section 3; `BspWalls.preciseWallSetup` |
| Vertex angles, view columns (`precisionFixes`) | `R_PointToAngle` through the 2048-entry `tantoangle` table; `viewangletox` / `xtoviewangle` on the 8192-step fine angle grid | `atan2` and exact tangent; `xtoviewangle` computed per column at full BAM precision | error of up to 1.4 pixels at 3440 columns | spec 04 section 3 |
| Floor and ceiling spans (`precisionFixes`) | span start from a fine-angle cosine/sine, `basexscale = cos/projection` in 16.16 (a 2 to 5% error at 2560+ columns), 16.16 steps | start and steps from the view direction in `double`, 32.32 position and step in the span drawer | finer span steps | spec 04 section 3; `Planes.mapPlanePrecise` |
| Sprites and masked walls (`precisionFixes`) | camera space from `finecosine`/`finesine` of the view angle, `FixedMul`/`FixedDiv` 32-bit | exact view angle, 64-bit screen positions and clamps, 32.32 texture steps; masked mid textures use the exact wall scale | no overflow near the camera, no sprite jitter against walls | spec 04 section 3 |
| Texture wrap | `& 127` | real texture height (already in W2-B, now `RenderOptions.correctTextureWrap()` documented) | spec 04 section 4 | |
| `finetangent` index overrun (vanilla mode) | index 4096 to 8191 reads the table that follows `finetangent` in memory (`finesine` from its start); crashes our bounds check | reproduced: `fineTangentOverrun` reads `finesine[i - 4096]` | found by the timedemo of freedoom2 DEMO1 at 320x200; also safe for Hor+ | `tables.c`, `r_segs.c:R_RenderSegLoop` |
| Square pixels (`video.aspectCorrection = false`) | n/a (320x200 always has 5:6 pixels) | projection from a `H x 4/3` 4:3 view (factor 5/6 of the corrected `H x 1.6`) so a 4:3 screen keeps a 90 degree horizontal field of view; the 2D layer keeps the uniform `H/200` scale (16:10 menus, as modern ports) | ADR-010 | spec 04 section 2 |
| Screen size 10 on a wide frame | `R_DrawViewBorder` draws no border when the view spans the width | same, so the 3D view fills the whole frame width above the status bar (Hor+); the status bar stays 320 virtual wide with the border flat at its sides | the UI used to paint side borders over the wide view | `Ui.drawViewBorder` |
| Interpolation | none | `doom.render.Interpolation` decorators over the views: actor position and angle, sector floor and ceiling heights, scrolling wall offsets, psprite offsets, eye height. Steps larger than any real motion (sectors 32 units, scrollers 16, psprites 48, eye height 32) are not interpolated, because the simulation does not snap the previous values of a new level or a loaded game | ADR-011; presentation only, the simulation is untouched (demos stay in sync) | spec 04 section 7 |
| Render pipeline settings | n/a | `render.precisionFixes` and `video.aspectCorrection` are read by the render adapter every frame | spec 04 sections 2, 3 | |
