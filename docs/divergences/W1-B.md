# W1-B: math foundation and test tooling

| area | original behaviour | ours | reason | reference |
|---|---|---|---|---|
| `FixedDiv(INT_MIN, 0)` | `abs(INT_MIN)` is still negative, so `(abs(a) >> 14) >= abs(b)` is false and the code divides by zero (undefined behaviour in C, crashes on x86) | `Fixed.div` throws `DoomFatalException` in that single case | no vanilla demo can reach it; a defined failure beats undefined behaviour | `m_fixed.c:FixedDiv` |
| `Tables` | trig tables are C array literals | one generated big-endian resource `doom/math/tables.bin` (SHA-256 pinned by `TablesTest`), produced by `gen-tables` from `tables.c`, `m_random.c`, `v_video.c` | a 10,240-element literal exceeds the 64 KB `<clinit>` limit (ADR-022 §8) | `tables.c`, `m_random.c`, `v_video.c` |
| Trace comparison | `trace-diff` gates every key but `m` | the comparator also reports key-order and missing-key differences as divergences; header differences (iwad, version, demo name case-insensitive) are notes only | the contract says lines must be byte-identical apart from `m`; a reordered key would hide a format bug | contracts §6.2, §6.7 |
| Synthetic demos | recorded by playing | generated from a seed (`SplittableRandom`), commands limited to vanilla keyboard values; the demo stores `angleturn >> 8` only | reproducible corpus; what the file holds is what the game reads back | `g_game.c:G_ReadDemoTiccmd` |
| Oracle runner | n/a | calls `tools/oracle/run.sh <iwad> <demo.lmp> -trace ...` with `ORACLE_LOG` set and decides success from the `timed N gametics` line in the console log | `run.sh` maps exit 255 to 0, and an engine `I_Error` (for example too few deathmatch starts) also exits 255, so the exit status alone cannot tell a finished demo from an engine error | `tools/oracle/run.sh`, `d_main.c`, `g_game.c:G_CheckDemoStatus` |
| Corpus: Freedoom E4M2/E4M3 | a player respawning in coop on a start with thing angle 360 reaches `I_Error("G_CheckSpot: unexpected angle 8192")` (Chocolate's silent-spawn emulation) | the corpus avoids it (E4M2 reseeded, E4M3 `b` is a deathmatch) so every oracle trace is complete; the game module must still reproduce this fatal error | an engine that ends the demo early cannot be compared tic by tic | `g_game.c:G_CheckSpot` (Chocolate 3.1.1) |
| `Iwads.assume*` | n/a | reaches JUnit's `Assumptions` reflectively | doom-testkit has no JUnit dependency in its POM (JUnit is test scope only); see the contract request in the W1-B report | ADR-015 |
