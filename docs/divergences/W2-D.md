# Divergences recorded by W2-D (engine, main loop, sound system, app)

| area | original behaviour | ours | reason | reference |
|---|---|---|---|---|
| Mouse input | `G_Responder` assigns `mousex`/`mousey` from each event: when several mouse events arrive between two tics only the last counts | Motion is accumulated between tics; the sub-unit remainder of `(sensitivity + 5) / 10` scaling is carried to the next tic | No lost motion at frame rates above 35 Hz (several frames per tic) | g_game.c:G_Responder |
| Mouse acceleration | Chocolate applies `mouse_acceleration` / `mouse_threshold` | Not implemented; sensitivity only | Modern raw input; spec 07 section 3 asks for X/Y sensitivity | i_input.c |
| Per-frame camera turn | Camera angle is the player angle of the last tic | The renderer camera adds the mouse turn not yet consumed by a tic (`LocalTicSource.pendingTurn`), on top of the interpolated angle | Spec 04 section 7 | - |
| Double click to use | `dclick_use`: double click on the forward or strafe mouse button sends BT_USE | Not implemented | Not part of the spec 07 binding model | g_game.c:G_BuildTiccmd |
| Key releases during menu | `G_Responder` is not reached while the menu eats events, but key-up events "always filter down" | Same for key-up; additionally focus loss releases every key and button | Avoid stuck keys after Alt-Tab | g_game.c:G_Responder |
| Always run | `joyb_speed >= MAX_JOY_BUTTONS` hack makes speed permanently 1 | `input.alwaysRun` inverts the run key (the key then walks) | Usual modern behaviour | g_game.c:G_BuildTiccmd |
| Gamepad | DOS joystick axes, digital or analog (`use_analog`) | GLFW gamepad: right stick turns, left stick moves and strafes, dead zone, cubic turn response, analog path of `G_BuildTiccmd` with `joystick_*_sensitivity` | spec 07 section 3 | g_game.c:G_BuildTiccmd |
| Pause key | `sendpause` writes a special ticcmd for the console player | The engine calls `GameSession.requestPause()` once per key press, before the next tic | The session owns the special command (contracts section 11) | g_game.c:G_BuildTiccmd |
| Sound pitch | `snd_pitchshift` is off: the pitch passed to `I_StartSound` is ignored | The random pitch is always drawn (misc RNG) and stored on the channel, but reaches the mixer only with `sound.pitchVariation = true` | Keeps the RNG sequence of vanilla (contracts section 8) while sounding like DOS | s_sound.c:S_StartSound |
| Sound channel lifetime | `I_SoundIsPlaying` asks SDL_mixer | A sound counts as playing until the audio thread has mixed two blocks after the start command, then the mixer's report decides; headless runs use the sample length in tics | The audio thread reports once per block, a just-started sound is not visible yet | s_sound.c:S_UpdateSounds |
| Level music | `S_Start` (from `P_SetupLevel`) picks the level's song | `SoundSystem.levelLoaded()` does the same on the `levelLoaded` event; a `changeMusic` of the same song from the session is a no-op | Works whichever of the two the session emits | s_sound.c:S_Start |
| Music pause on level start | `S_Start` clears `mus_paused` without resuming the player | A paused song is resumed first | A song stuck paused is never wanted | s_sound.c:S_Start |
| Missing sound lump | `W_GetNumForName` error | Warning at debug level; the sound is silent (channel logic and RNG draw unchanged) | Shareware and Freedoom lack some DOS sounds that DEHACKED or PWADs may still request | i_sound.c:I_GetSfxLumpNum |
| Quit | `I_Quit` after the quit sound, waiting 105 tics | The loop continues for 1.5 s when audio is active, then exits; closing the window quits at once (no "quit?" confirmation) | Window system convention | m_menu.c:M_QuitResponse |
| Wipes | `wipegamestate` set in `D_Display`; time keeps running (tics are caught up afterwards) | Same trigger (game state change or `forceWipe`); the clock is shifted by the wipe time so no tics are caught up ("the wipe pauses the simulation", spec 02 section 7) | Spec | d_main.c:D_Display |
| Headless runs | Chocolate with the dummy SDL driver draws, wipes and updates the status bar | No drawing, wipes or UI: the misc RNG index (trace key `m`, informational) differs; gated keys are unaffected | Speed; contracts section 6.2 | - |
| Timedemo output | `I_Error("timed %i gametics in %i realtics (%f fps)")`, exit status 255 | Prints the same text (one decimal) on the output stream and exits 0; frames per second is printed too when windowed | Not an error | g_game.c:G_CheckDemoStatus |
| Config file | `default.cfg` (`name value`) | `doom-java.cfg` (`key = value`, `#` comments), per-OS data directory, lenient parsing with warnings | ADR-017, spec 07 section 4 | m_config.c |
| Window resolution | 320x200 | Internal resolution follows the output size (spec 04 section 2); `-vanilla` keeps 320x200 | ADR-010 | - |
