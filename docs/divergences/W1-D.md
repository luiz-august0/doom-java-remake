# Divergences recorded by W1-D (audio: formats, OPL3, music driver, mixer, Java Sound)

| area | original behaviour | ours | reason | reference |
|---|---|---|---|---|
| mus2mid | Per-channel velocities and the queued time are static: a song converted after another inherits the last velocities of the previous song | Every conversion starts from velocity 127 on all channels | Deterministic per song; identical to Chocolate for the first song of a process, which is what the byte-for-byte test compares (each lump is converted in a fresh process) | mus2mid.c:channelvelocities |
| mus2mid | `CHECK_MUS_HEADER` is not defined: the MUS signature is not checked, header fields are read as is | Same (no signature check), but a score start beyond the lump or truncated data throws `WadFormatException` | Never an uncontrolled exception on bad PWAD data (spec 02 §9) | mus2mid.c:mus2mid |
| Music lump type | `MThd` lumps up to 96 KiB are MIDI; larger ones are treated as MUS and fail | A lump starting with `MThd` is MIDI at any size | Larger PWAD MIDI files simply work | i_oplmusic.c:I_OPL_RegisterSong |
| MIDI parsing | `program change` / controller / key parameters are used unmasked and index tables out of range if bit 7 is set | Parameters are masked to 7 bits where they index a table (instrument number, volume tables) | Memory safety; valid files are unaffected | i_oplmusic.c |
| Sequencer | Tracks of a format 1 file run as separate timer chains with microsecond callbacks | Same: `MusicScore` keeps the per-track chain and delta, the player schedules one callback per track in the same 64-entry heap. Merged order is only informative | Needed to reproduce Chocolate's register order bit for bit | opl_sdl.c, opl_queue.c |
| Music timing | Callbacks are quantised to audio samples and depend on the SDL_mixer chunk size (4096 frames at 44.1/48 kHz) | Same algorithm; the quantisation depends on the block size the engine renders (256-512 frames) | Differences are below one sample per block; tests compare with the same block size on both sides | opl_sdl.c:OPL_Mix_Callback |
| OPL init | `OPL_Init` detects the chip with timer reads and `OPL_Delay`, then `OPL_InitRegisters` | Detection skipped; `OPL_InitRegisters` writes are reproduced; writes to registers 2, 3, 4 (timers) are not sent to the chip, as in `opl_sdl.c` | There is no hardware to detect | opl.c, opl_sdl.c |
| Music volume | `S_SetMusicVolume(level * 8)` | `setVolumes(sfx, music)` takes 0-15 and passes `music * 8`; initial level 8 (64) | Menu scale of the original | s_sound.c |
| SFX resampling | SDL_mixer / SDL_AudioCVT conversion, nearest sample for the ratios DOOM uses | Linear interpolation by default (spec 06 section 2), nearest selectable (`linearInterpolation = false`) | Spec choice; nearest is closest to the raw sound | i_sdlsound.c:ExpandSoundData |
| SFX pan law | `Mix_SetPanning(left = (254 - sep) * vol / 127, right = sep * vol / 127)` linear gains | Same linear law (a centred sound is 6 dB below hard-panned) | Spec 06 says "constant-power"; contracts say Chocolate wins. Behaviour matches DOS DMX | i_sdlsound.c:I_SDL_UpdateSoundParams |
| SFX mixing | SDL_mixer sums in 16 bit with saturation | `int` accumulation and an integer soft limiter (linear below 24576, rational knee towards 32767) | Spec 06 section 2 | - |
| SFX pitch | `snd_pitchshift` (off by default) resamples the sound to `(2 - pitch/128)` of its length | If a pitch other than 128 is passed, playback speed is `128 / (256 - pitch)` (capped at 4x) | Equivalent, done at mix time without a second sample copy | i_sdlsound.c:PitchShift |
| SFX channels | 16 SDL_mixer channels | 8 by default, up to 32 | Spec 06 section 1 | - |
| DMX sound padding | The first and last 16 bytes of the sample area are skipped; lumps with 48 samples or fewer are ignored | Same; additionally a sample rate of 0 is rejected | A zero rate divides by zero in Chocolate | i_sdlsound.c:CacheSFX |
| Output latency | SDL audio device | `SourceDataLine` with a 2-block (1024 frame, 21 ms) buffer; see docs/notes/audio-latency.md | ADR-012 | - |
